Section 05 · Root Causes

Architectural Vulnerability Patterns & Root Cause Analysis

Why Tutor LMS, LearnPress, and LearnDash exhibit completely different security risk profiles

1

Tutor LMS: Custom AJAX & SQL Regressions

Themeum implemented dozens of custom wp_ajax_ actions and dynamic SQL queries rather than standard WordPress query abstractions. This design created recurring authorization flaws, where nonces were validated without verifying user capabilities or permissions.

  • • Over 65 SQLi and IDOR flaws logged
  • • Repetitive capability check bypasses
  • • Frequent fast-paced hotfix cycles
2

LearnPress: Public REST & Unescaped Queries

ThimPress constructed customized REST routes that took complex JSON payloads directly into SQL statement fragments without using prepared statements ($wpdb->prepare). This created massive unauthenticated attack vectors.

  • • Multiple unauthenticated CVSS 10.0 / 9.8 SQLi
  • • Path traversal and arbitrary file reads
  • • Slow patch turnaround (14-30+ days)
3

LearnDash: Native CPT Abstraction

StellarWP adheres to core WordPress conventions: courses, lessons, and quizzes are standard Custom Post Types (sfwd-courses). Queries rely on WP_Query and core permissions, reducing raw SQL surface area by 85%.

  • • Only 14 confirmed core CVEs over 14 years
  • • Strict enterprise code review pipelines
  • • 24-48h security patch SLA
